# 技术方案

## 技术选型

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 工程 | Vite 8 + TypeScript | 本地迭代、静态产物、模块化代码 |
| 渲染 | Three.js / WebGL 2 | 几何场景、相机、灯光、阴影与模型扩展 |
| 物理 | @dimforge/rapier3d-compat | 浏览器 WASM 物理、角色碰撞和刚体 |
| 界面 | HTML/CSS + Canvas 小地图 | 当前 UI 规模无需引入额外组件框架 |
| 保存 | localStorage + 版本化数据 | 单机原型本地保存，隔离读写以便扩展 |
| 发布 | 静态托管 | 游戏计算运行于玩家浏览器 |

具体版本以 `package-lock.json` 为准，使用 `npm ci` 复现依赖。推荐 Node.js 24 LTS。

## 运行顺序

1. `main.ts` 立即创建 UI 和加载提示。
2. 异步导入游戏模块，初始化 Rapier WASM。
3. 创建 Three.js 渲染器、Rapier 世界、街区、角色和汽车。
4. 用户点击开始后处理输入、固定时间步物理和任务。
5. 按浏览器刷新率渲染，每 0.1 秒更新 HUD 和小地图。

物理使用 1/60 秒固定步长、累积器和最长单帧 0.1 秒的补算上限，避免掉帧后无限追赶。任务倒计时按实际经过的前台运行时间更新，不随物理补算上限减慢。暂停会停止玩法和计时，页面隐藏自动暂停。渲染循环仍保留静态画面。

## 模块职责

- `core/Game.ts`：系统协调、更新顺序、相机、交互、上下车和生命周期。
- `core/Input.ts`：按键保持、单次按下、鼠标拖动、失焦清理。
- `core/mission.ts`：纯任务状态机，不依赖 DOM 或渲染。
- `core/save.ts`：存档格式验证与异常降级。
- `actors/Player.ts`：胶囊体、Rapier CharacterController、跳跃、同一人物的上下车挂接与恢复。
- `actors/Character.ts`：GLTFLoader 加载本地人物，AnimationMixer 混合待机/步行/跑步动画，驾驶位骨骼姿态和手臂双段 IK，第一人称头部/躯干遮挡处理。
- `actors/Car.ts`：简化刚体汽车、纵向速度、横向阻尼和转向。
- `world/city.ts`：程序化街区、固定碰撞体、店铺标牌和目标标记。
- `ui/Hud.ts`：UI、小地图、提示、开始/暂停/错误界面。
- `ui/Radar.ts`：以玩家为中心、随视角旋转的圆形雷达，包含方向标和圆边任务提示；`ui/retro-hud.css` 独立管理复古状态面板和雷达外观。

目前 `Game` 直接协调系统；当追捕和交通引入后，再拆出交互系统和道路导航模块。

## 资源规范

街区和车辆通过 Three.js 几何和 Canvas 生成。人物使用本地 `public/models/casual-character.glb`（Quaternius Casual Character / CC0），启动时与 Rapier 并行加载，成功后开放开始按钮。运行游戏时不向模型来源站点请求资源。来源及 SHA-256 见 `public/models/ATTRIBUTION.md`。

`.env.example` 的 `VITE_ASSET_BASE_URL` 只是后续资源加载器的预留约定，当前代码尚未读取该值。人物 GLB 使用 Vite `BASE_URL` 解析同源路径；后续更多资源可接入统一加载器、可配置资源域名、加载进度和重试。只有浏览器可公开的数据才能使用 `VITE_` 环境变量，密钥应保留在未来的服务端。

模型采用米作为单位。纹理、模型、音效均通过版本或内容哈希管理缓存，避免直接替换同名缓存资源。

## 当前取舍与风险

- Rapier compat 内嵌 WASM，游戏模块会达到数 MB，首次下载需要时间。已将整个游戏异步加载，界面可以先展示；构建体积提醒保留，后续按需求评估独立 WASM 和压缩。
- 车辆暂时锁定俯仰和翻滚，用速度控制实现街机手感；不是射线轮胎、悬架或完整动力学。后续驾驶阶段改进。
- 几何体较多，当前逐个创建 Mesh；性能阶段可合并静态几何或用 InstancedMesh。
- 目前相机使用射线处理遮挡，复杂狭窄空间仍需继续打磨。
- 步行/车外镜头降低高度，略向前看以保留地平线。车内相机直接绑定车辆局部驾驶席位置，使用独立近裁剪距离与 72° 视野，防止跟随插值将视点拖出车厢；车身采用中空车厢、透明车窗与简单内饰。V 切换时直接切镜，车内左右环视限制在约 ±72°，松开后回正。
- 本地存档可被玩家修改，适合单机体验；正式排行榜必须由服务端验证成绩。
- 当前 HMR 清理动画混合器、骨骼纹理、渲染器、几何、材质、纹理、输入监听器和物理世界。

驾驶时禁用步行刚体，将人物视觉节点挂到汽车下，并把骨盆定位在座垫上。手脚使用两段骨骼求解；源模型的脚骨位于 Root 下，需要独立更新。上下车恢复中立骨骼姿态，车内仅隐藏头部及会挡住视野的衣服/裤子网格，真实手臂仍可见。当前没有开车门和连续入座动画。

## 扩展接口

- 云存档：将独立的本地存档读写升级为带认证的异步接口。
- 官网/账号中心：可独立引入 Next.js，保留游戏模块的浏览器运行方式。
- 交通/警察：共用道路图，巡逻和追赶使用独立状态机。
- 多人游戏：另行设计权威服务器、同步、插值、输入验证与断线恢复。
